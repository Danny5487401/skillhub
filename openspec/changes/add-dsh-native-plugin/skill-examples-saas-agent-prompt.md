# SaaS Agent 增量任务：版本化多语言技能案例

以下正文可以直接交给拥有SaaS仓库访问权限的Agent。当前任务是接入固定案例文件协议，不重做已有DSH Registry支持。先输出基于真实代码的差异表，再按SaaS项目流程研发、测试和提交PR；没有授权不要部署生产。

## 目标与先读资料

让同一个新SkillHub CLI/DSH候选能够从SaaS发布、下载并安装带`.skillhub/examples.json`的技能，原始文件完整保留，案例选择和真实技能占位符由DSH本地处理。

开源权威资料：

- `openspec/changes/add-dsh-native-plugin/skill-examples-design.md`：路径、协议、语言回退、内部记录与兼容边界。
- `openspec/changes/add-dsh-native-plugin/contracts/skill-examples.schema.json`及valid/empty样例：唯一协议契约。
- `openspec/changes/add-dsh-native-plugin/skill-examples-execution-plan.md`：范围、验收与阶段顺序。
- `openspec/changes/add-dsh-native-plugin/registry-api-contract.md`：已有HTTP访问规则。

开源工作分支已完成本功能及本地验收，但尚未提交或发布。移植前确认通过验收的最终开源提交和双方真实差异，以运行代码、测试和本文契约为依据；开源本地通过不代表 SaaS 已兼容。

## 协议概要

文件是技能包的版本化作者资源，不是安装后生成的缓存，不独立刷新。根包含schemaVersion、defaultLocale、examples；examples按语言标签分组，每条含id/title/prompt，同一逻辑案例跨语言同id。prompt中的精确`{{skill}}`由DSH使用核验后的真实调用替换，服务端不替换、不执行、不翻译。

合法协议识别为案例；错误JSON、结构或不支持协议按普通文件保留，不阻断正常技能发布；通用包大小/路径/安全规则仍有效。缺失文件不影响旧技能。不要兼容此前讨论但已废弃的字符串数组、外置缓存或单独案例表方案。

## 第一步：差异调查

逐项给出“实际类/方法或路由、现有行为、缺口、拟改位置、测试方式”：

1. ZIP提取和包根归一化、Windows路径/大小写及重复目标处理。
2. .skillhub是否被目录上传、包重建、扫描输入、对象存储或下载链路排除。
3. 文件manifest、每文件SHA、resolve聚合fingerprint和下载ZIP是否覆盖全部作者文件。
4. 上传metadata是否被信任或覆盖，预检与正式发布是否走相同规则。
5. 是否已有包预检摘要、原始文件流接口和可选字段向后兼容机制。
6. 审核/复制/版本切换/删除中间层是否保留文件和访问隔离。

不要猜测与开源同名类，也不要先创建表或新接口。已经符合的部分只补验证，不为对齐开源结构而重构。

## 第二步：实现最小差异

### A. 文件与内部记录

- 原样保存`.skillhub/examples.json`，包括无法识别为协议但通过通用包校验的文件。
- `.skillhub/metadata.json`仅安装器所有，不允许作者上传的身份进入发布包。Web目录打包可精确排除；手工ZIP/直接API在服务端归一化后明确拒绝，不静默覆盖。
- 允许的其他作者文件按普通内容保留，不能整体过滤.skillhub或忽略所有JSON。
- 不新增任意路径读取，不放宽路径穿越、符号链接、跨租户、私有/撤回/未审核访问规则。

### B. 协议识别与Web体验

- 按schema和补充语义验证：默认语言存在、规范化语言不重名、同语言id不重复、Unicode长度和字节上限一致。
- 在现有预检区域展示“已识别案例”或简短非阻断格式提示，不增加案例编辑器或语言设置表单。
- 若采用开源预检投影，新增可选examplesStatus/examplesCount，并同步OpenAPI/消费类型。count统一统计全部语言条目总数；合法非空为ready，合法全空或无文件为none且count=0，invalid省略count，旧响应缺字段视为未知；不只统计默认语言。
- 预检输出不创建第二份服务端可变案例；源文件仍是唯一内容。

### C. 分发与指纹

- 复用现有版本文件和对象存储，不新增案例数据库表；若声称必须迁移先解释当前存储为何不能保存普通JSON文件。
- resolve指纹覆盖的路径/哈希与新消费者快照一致，合法及非法案例都参与。保持既有算法，若已包含全部作者文件则不改。
- 已有精确版本file接口足够时直接复用，返回原始字节，不加ApiResponse包装；本地Use不需要服务端新案例端点。
- 缺失、读取失败、拒绝访问、限流或不可见不可混同；不要为新案例顺带重构通用错误码。实际语义如影响新消费必须单独列明。

## 第三步：测试与联验

使用隔离测试技能和新版本，不改现网作者内容。至少覆盖：

- 无案例旧技能；中英文及第三语言；同id翻译/不同语言条数；默认回退与显式空集合。
- 错误JSON/未知版本/重复id/过长文本按普通内容发布且字节不变；危险包仍被拒绝。
- CLI目录、Web目录、手工ZIP、直接API；metadata路径别名、重复目标、大小写冲突和符号链接。
- 发布审核后的文件清单、原始file读取、下载ZIP与resolve指纹逐一一致。
- 私有、跨租户、撤回和不可见版本保持原规则。
- 新CLI/DSH候选接测试Registry，完成安装→多案例选择→原生草稿→升级→卸载；用户/项目两个范围各验，不自动发送。

旧消费者兼容不能用源码猜测通过。至少记录旧→旧、新→旧、新→新、旧→新包的实际结果；某些旧CLI删除/force会按原规则执行，不能承诺被新协议阻止。历史包指纹/ZIP不能回算；不支持的历史子集先列出，不自动迁移。
