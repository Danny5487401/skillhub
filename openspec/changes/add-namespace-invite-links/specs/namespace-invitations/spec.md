## Purpose

让 Namespace 管理员使用可控的短期单次链接邀请新成员。

## ADDED Requirements

### Requirement: REQ-INV-01 管理员 SHALL 创建、替换及作废邀请

有权管理员 SHALL 可创建、替换及作废邀请。

只有 ACTIVE TEAM 的 OWNER/ADMIN 可以创建邀请；平台角色不能绕过成员角色限制。每个 Namespace 仅有一条当前邀请，24 小时内仅一名非成员可兑换一次。替换仍可用的邀请前须确认，创建响应仅在旧链接当时仍可兑换时标记 `replaced=true`；已消费或过期后的新建不标记替换。管理员可以单独作废当前邀请，且已加入成员不受影响。

#### Scenario: 替换未使用链接
- **WHEN** 管理员再次点击邀请且当前链接仍可兑换
- **THEN** 页面先说明旧链接将失效并要求确认
- **AND** 仅确认后生成新链接，旧链接立即失效

#### Scenario: 单独作废
- **WHEN** 管理员点击作废并确认
- **THEN** 当前链接立即失效，不会创建新链接或移除成员

### Requirement: REQ-INV-02 邀请 SHALL 服从现有账号准入

邀请 SHALL 服从现有账号准入规则。

邀请只授予目标 Namespace 的 MEMBER 权限，不使用户绕过现有注册、登录、外部身份准入和账号审批。接受者必须先拥有可用登录会话，看到目标 Namespace、当前账号和 MEMBER 可访问及发布资源的说明，再明确确认加入。页面加载不得自动兑换。

#### Scenario: 新用户未通过准入
- **WHEN** 持链接者无法按既有策略获得可用账号
- **THEN** 邀请不能使其进入目标 Namespace

#### Scenario: 已登录非成员
- **WHEN** 非成员打开有效链接
- **THEN** 页面展示 Namespace、账号和权限，只有点击确认才新增 MEMBER

### Requirement: REQ-INV-03 Token SHALL 避免意外泄露

Token SHALL 避免出现在日志、持久化明文和登录 URL 中。

Token 使用安全随机数，数据库仅保存哈希；原文只在生成响应中出现一次。创建者页面可将原文保存在按账号和空间隔离的当前标签页 sessionStorage，供重开弹窗或刷新后恢复；展示前须重新确认服务端 active 状态并预览该 Token，失效或替换时清除。不得存入 localStorage 或数据库明文；其他标签页或设备无法恢复时明确说明，并保留确认替换入口。分享 URL 使用 `/join#invite=<token>`，页面立即移入当前标签页 sessionStorage 并清除 fragment；登录回跳只包含应用内 `/join`，不带 Token。创建、预览、兑换、作废响应禁止缓存；日志和审计不得包含原文或哈希。四类操作仅允许浏览器 Session，变更请求遵守 CSRF。
Token 原始随机字节不得少于 32 字节，并采用 Base64URL 编码；数据库仅保存 SHA-256 哈希。

#### Scenario: 经过登录回跳
- **WHEN** 未登录者打开邀请后登录
- **THEN** Token 不出现在登录回跳 URL，回到原标签页后才从 sessionStorage 恢复邀请

#### Scenario: 子路径部署
- **WHEN** 应用部署在 `/skillhub/`
- **THEN** 分享链接指向公开基地址下 `/skillhub/join#invite=<token>`，应用内 returnTo 仍为 `/join`

### Requirement: REQ-INV-04 服务端 SHALL 在接受时重新判断状态

服务端 SHALL 在接受邀请时重新判断全部状态。

预览不消费邀请。接受时重新检查 Token 是否仍为当前、用户是否已有成员关系、Namespace 是否 ACTIVE TEAM、邀请是否未消费且未过期。Token 匹配当前邀请且用户已是成员时返回 ALREADY_MEMBER，不再检查过期、消费或 Namespace 冻结归档状态，也不消费。未知、过期、替换、作废或已用 Token 对非成员返回统一失效响应。冻结或归档时非成员不能加入也不消费，恢复后仅在原有效期内可兑换。
统一失效响应使用 HTTP 404、envelope `code=404` 与 `data=null`；前端只按状态处理，不解析本地化文案。

#### Scenario: 预览后链接被替换
- **WHEN** 用户看到预览后管理员替换或作废了链接
- **THEN** 接受请求失败且不新增成员

#### Scenario: 已有成员打开当前链接
- **WHEN** Token 仍是当前邀请且当前用户已经是成员
- **THEN** 返回 ALREADY_MEMBER，直接进入 Namespace，不消耗邀请

#### Scenario: 被移除者重用已消费链接
- **WHEN** 曾兑换的成员后来被移除
- **THEN** 原链接仍保持已消费，不能再次加入

### Requirement: REQ-INV-05 并发操作 SHALL 保持成员和邀请原子一致

并发操作 SHALL 保持成员和邀请原子一致。

邀请创建、替换、作废和接受与成员添加/删除/转交、Namespace 冻结/归档/恢复/删除、账号合并在相同 Namespace 上须串行化。涉及用户和 Namespace 的写操作先按用户 ID 升序、再按 Namespace ID 升序加锁；创建/替换/作废及带操作者审计的生命周期操作锁操作者，接受锁接收者；当前不写用户审计的 Namespace 删除只锁 Namespace。接受时成员创建、邀请消费和审计同一事务完成；并发兑换最多一名非成员成功，不能产生“已消费但无成员”。批量涉及多个 Namespace 的操作按去重 ID 升序锁定。

#### Scenario: 两人同时兑换
- **WHEN** 两个非成员同时确认同一链接
- **THEN** 最多一人新增 MEMBER，另一人收到统一失效结果

#### Scenario: 管理员直接添加与邀请并发
- **WHEN** 管理员直接添加同一用户和该用户兑换邀请同时发生
- **THEN** 不出现未处理的唯一约束异常、重复成员或错误消费

### Requirement: REQ-INV-06 前端 SHALL 完成链接分享和状态闭环

前端 SHALL 完成链接分享、登录回跳和邀请状态闭环。

空间卡片收拢为进入空间的主要入口；空间管理详情按技能、成员、审核、设置组织，邀请集中在成员页弹窗，提供生成、替换确认、复制失败后的手动复制以及单独作废；冻结、归档及恢复等原有治理动作集中在设置，保留权限及确认。接收页提供加载、确认、已加入和失效状态。成功、已加入或终态失效时清除 sessionStorage 中的 Token；已加入预览一旦成功即清除 Token 并自动使用 replace 导航进入空间，避免重复导航。加载状态使用可访问的 status 提示，终态失效使用 alert 提示。网络错误保留 Token 以重试。生成公开链接必须复用现有公开基地址解析方式，清理 fragment 时保留当前 path 和 query。中文、英文和俄文文案均覆盖。

#### Scenario: 剪贴板写入失败
- **WHEN** 创建成功但浏览器拒绝写剪贴板
- **THEN** 页面显示同一链接供手动复制，不再次生成邀请

#### Scenario: 网络错误
- **WHEN** 预览或接受遇到可重试网络错误
- **THEN** 页面保留 Token，用户可重试而无需新邀请

### Requirement: REQ-INV-07 API SHALL 使用 Issue #911 的路径与响应合同

API SHALL 使用 Issue #911 的路径与响应合同。

创建或替换使用 `POST /api/v1/namespaces/{slug}/invitations`，首次创建允许无请求体；有仍可兑换的当前邀请时须按已批准的确认流程传入 `replace=true`。状态查询和单独作废分别使用同一路径的 GET 与 DELETE。预览和接受分别使用 `POST /api/v1/namespace-invitations/preview` 与 `POST /api/v1/namespace-invitations/accept`，请求体均为 `{ "token": "..." }`；可保留 `/api/web` 别名。

创建数据仅包含 `token`、`expiresAt`、`replaced`。预览数据包含 `namespaceSlug`、`namespaceDisplayName`、`namespaceAvatarUrl`、`outcome`（`CONFIRM_REQUIRED` 或 `ALREADY_MEMBER`）和 `expiresAt`。接受数据仅包含 `namespaceSlug` 和 `outcome`（`JOINED` 或 `ALREADY_MEMBER`）。无效邀请使用 `error.namespace.invitation.invalid` 本地化键，中文为“邀请链接无效或已失效”，响应为 HTTP 404、envelope `code=404`、`data=null`。

#### Scenario: 首次创建和预览
- **WHEN** OWNER/ADMIN 首次创建邀请且不传请求体，非成员预览链接
- **THEN** 创建返回三字段，预览返回五字段且 `outcome=CONFIRM_REQUIRED`

#### Scenario: 接受与已有成员
- **WHEN** 非成员确认加入，或已有成员访问当前邀请
- **THEN** 接受分别返回 `JOINED` 或 `ALREADY_MEMBER`，且仅包含 `namespaceSlug` 和 `outcome`

#### Scenario: 旧邀请与无效新邀请
- **WHEN** 接收者打开旧的 `/join#<token>` 链接
- **THEN** 按原方式安全捕获并清除片段，保持兼容
- **WHEN** 新的具名片段格式无效
- **THEN** 清除先前暂存凭证，不能误用上一条邀请；无片段的登录回跳仍恢复合法暂存邀请

#### Scenario: 他人消费邀请后生成新链接
- **WHEN** 他人已消费邀请，而管理员页面还缓存旧的可兑换状态
- **THEN** 点击生成先刷新服务端状态，已消费或过期的邀请不误弹替换确认，仍可兑换的邀请必须确认
- **AND** 状态刷新失败时不沿用旧缓存生成或替换，显示可重试错误

#### Scenario: 重开邀请弹窗与成员页布局
- **WHEN** 同一账号在同一标签页重开弹窗或刷新成员页
- **THEN** 重新校验有效的已保存链接后显示，并提供复制；失效或替换的链接不展示
- **AND** 无保存链接时说明限制，不自动替换邀请
- **AND** 返回我的空间位于空间标题上方；无管理权限不显示成员变更按钮；有权限的角色保存、取消和移除放在操作列，图标有可访问名称及悬停提示
- **AND** 审核状态采用带标签的下拉筛选，与空间主导航区分

#### Scenario: 邀请弹窗提供完整状态及说明
- **WHEN** 有权管理员打开邀请弹窗
- **THEN** 显示目标空间及邀请有效／无有效邀请／加载／读取失败状态；可恢复原链接时显示实际到期时间及复制入口
- **AND** 说明24小时内单次使用、MEMBER权限、先登录及现有准入规则；替换和作废操作独立于复制，并继续要求确认
- **AND** 读取失败可重试；桌面弹窗适当增宽，手机仍可完整操作

### Requirement: REQ-INV-08 系统 SHALL 保留独立邀请记录

每次成功生成邀请 SHALL 创建一条具有独立标识的邀请记录，保存创建人、创建时间、到期时间及生命周期结果。再次生成、替换或作废 SHALL NOT 覆盖或删除之前的业务历史记录。记录可展示有效、已使用、已替换、已作废、已过期状态；过期状态按真实到期时间判定，不要求依赖定时任务才失效。

新成员通过邀请成功确认加入时 SHALL 将实际加入账号及加入时间准确关联至该次邀请记录。只打开或预览链接、不成功兑换或已有成员访问 SHALL NOT 被记录为新的加入成功。邀请记录 SHALL NOT 展示原始 Token 或 Token 哈希，历史记录不构成恢复已失效链接的入口。

本条为2026-10-14确认并实现的新增需求，执行验证以本次验收记录为准。空间存在期间持续保留邀请业务记录，不新增保留期配置；彻底删除空间时删除其邀请业务记录，操作审计按既有规则保留。升级仅迁入仍能准确读取的当前邀请并标注旧记录；不可可靠关联的更早审计不得拼造为邀请历史。用户退出或被移除后仍保留当时的成功加入事实；账号改名或合并不改写原邀请账号归属，记录不代表当前成员资格。

#### Scenario: 邀请已使用后再次生成
- **WHEN** 邀请A被张三成功使用，管理员随后生成邀请B
- **THEN** A保留已使用状态及张三的加入时间，B为新的独立记录

#### Scenario: 替换或作废邀请
- **WHEN** 管理员替换仍有效的邀请A，或作废邀请B
- **THEN** A或B保留各自已替换或已作废记录，不覆盖先前的加入记录

#### Scenario: 预览不记为加入
- **WHEN** 用户仅打开邀请页或预览链接，未成功确认加入
- **THEN** 不产生邀请加入成功记录

### Requirement: REQ-INV-09 邀请历史 SHALL 按空间管理权限限制访问

邀请历史页面和查询接口 SHALL 仅允许该空间OWNER或ADMIN访问。普通成员不得查看；平台角色不自动绕过空间成员角色规则。权限判定采用当前身份及当前空间角色，不能仅依赖前端隐藏入口。

#### Scenario: 普通成员或仅有平台角色的账号查看历史
- **WHEN** 当前账号不是该空间OWNER或ADMIN
- **THEN** 页面不提供历史查看入口，直接调用查询接口也不能获得记录

#### Scenario: 空间管理员查看历史
- **WHEN** 当前账号具有该空间OWNER或ADMIN角色
- **THEN** 可查看该空间邀请记录，不可据此查看其他空间记录

#### Scenario: 删除空间与历史保留
- **WHEN** 空间被彻底删除
- **THEN** 删除该空间的邀请业务记录，现有操作审计按原规则保留；归档或冻结不等同于彻底删除

#### Scenario: 升级迁入旧邀请
- **WHEN** 升级前存在可准确读取的当前邀请
- **THEN** 将其已知创建及消费信息迁入并标注为旧记录，不伪造更早记录的链接关联

#### Scenario: 加入后退出或被移除
- **WHEN** 通过邀请加入的用户后来退出或被管理员移除
- **THEN** 历史仍显示当时的加入事实，不据此授予或恢复成员权限

### Requirement: REQ-INV-10 邀请弹窗 SHALL 提供只读分页历史

现有邀请弹窗 SHALL 在上方保留当前链接及生成／替换／作废操作，下方直接显示邀请记录，不增加嵌套标签页。历史最新在前并分页，网页默认每页5条并限制列表高度；人员优先显示记录时保存的姓名或显示名称，不平铺完整user_id，完整标识保留在悬停提示及可访问说明中；无姓名的旧记录以缩短标识兜底。展示创建人及时间、到期时间、有效／已使用／已替换／已作废／已过期状态、实际加入人及加入时间；旧迁入记录明确标注。历史不显示原始链接、Token或哈希，不提供复制或恢复失效链接操作。列表支持加载、空列表、失败及重试状态；不同空间记录不得串用，成功变更邀请后刷新列表。

#### Scenario: 管理员在同一弹窗查看历史
- **WHEN** 空间OWNER/ADMIN打开邀请弹窗
- **THEN** 当前邀请操作与只读历史同时可访问；列表按最新在前分页，手机端可阅读和翻页

#### Scenario: 成功变更邀请刷新历史
- **WHEN** 管理员成功生成、替换或作废邀请
- **THEN** 列表刷新并展示对应记录和状态；取消确认不新增记录

#### Scenario: 历史读取失败
- **WHEN** 历史查询请求失败
- **THEN** 显示失败及重试入口，不能将其他空间缓存记录展示为当前空间历史

#### Scenario: 冻结或归档空间查看历史
- **WHEN** TEAM空间被冻结或归档，当前账号仍为该空间OWNER或ADMIN
- **THEN** 可打开只读历史入口，不开放当前邀请生成／替换／作废操作，历史读取不依赖变更权限
