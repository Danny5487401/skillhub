## Context

当前 Skill 无头像字段。详情、搜索和“我的技能”由不同查询路径投影，Web 卡片与详情也没有统一头像组件。`ObjectStorageService` 支持写入、读取和删除，但本地实现不产生预签名 URL。现有 ReviewTask 只处理 SkillVersion/SuiteVersion；头像不能伪装成版本审核。V68 已提供 versioned `system_setting`。

## Decisions

1. 为 Skill 保存当前已激活头像引用；另建头像候选及决定记录。候选包含所属 Skill、提交者、私有对象键、内容哈希、目标可见范围、提交时审核策略快照、机器结果、人工决定、状态和时间。所有状态转移按候选 ID 和当前候选 ID 条件更新，防止迟到结果覆盖。
2. 头像人工决定复用现有 ReviewTask、技能审核队列与 ReviewPermissionChecker。技能包与头像同次提交时关联同一版本审核任务；单改头像使用元数据审核任务，不创建 SkillVersion。头像候选保留图片、机器结果和审计，不作为另一套人工审核流程。上传 API 显式校验 `skill.ownerId == actor`；审核权不授予代传权。
3. 图片通过受控 GET 接口提供。私人和待审对象必须鉴权，当前公开头像可提供稳定、无时效的访问 URL；服务端不得将对象存储临时签名地址持久化。公开范围变更之前须重新判断头像是否已获目标范围许可，避免私人图片借 Skill 可见性变化直接泄露。
4. 上传只接受最终裁剪图，服务端独立解码、校验、重新编码并去掉元数据。上限和格式以现有上传约定及测试验证后在实现中固定，避免前端校验成为唯一防线。
5. `system_setting` 新增独立头像审核键，仅保存机器和人工开关。部署配置只允许一个供应商及其 Secret；后台不展示供应商或 Secret。适配器在服务端主动调用，供应商异常保留候选和重试，不自动通过。供应商实现与 API 参数在接入时以官方文档验证。
6. 开关在提交候选时快照。PRIVATE 且仅所有者可见直接激活；其他候选按照快照执行。机器通过且人工关闭可激活；机器阻止时允许例外申诉；人工开启时有权审核员可改判并留理由。
7. 替换待审候选时旧候选变为 SUPERSEDED。删除和管理员撤下立即取消当前头像并恢复兜底。失效图片保留私有 30 天，再由有界清理任务删除；审计记录不随图片删除。
8. `SkillSummaryResponse` 的所有映射路径、详情 DTO 与生成类型包含当前头像 URL；Web 使用一个头像/兜底组件，所有者操作和审核队列分别展示其可执行动作。

## Risks and verification

- 私人候选和已发布头像的读取权限用非所有者、匿名和跨团队请求验证。
- 上传、更换、审核和撤下并发时验证当前候选不被旧结果激活。
- V68 后迁移在已有数据上通过；旧 Skill 无头像时无需回填。
- 服务端图片解码处理需设置资源上限；机器供应商凭证不得进入日志、数据库或前端。
- 原 Issue 的“机器不得直接拒绝”与本轮方案不同。机器单开模式的质量和误判处理需在运行验证中单列，不以外部 API 返回成功代替有效审核验证。


## 已确认的发布交互调整（2026-10-13，已实施，浏览器验收通过）

本节补充原实现，需求以 `specs/skill-avatars/spec.md` 的 REQ-AV-09/10/11 为准。

- 新增和更新页面使用可选自定义上传，不提供预设图标；更新默认保留，支持替换及移除。
- “我的技能”提供单独修改头像入口，不要求新版本；详情页保留展示与审核状态，移除完整上传表单。统一复用裁剪和上传组件。
- 先私有上传、后业务提交：新增技能尚无 Skill ID，临时上传不能提前创建已绑定的头像申请。上传引用绑定提交者并校验可用性，临时阶段不改变当前头像或待审申请。
- 技能提交成功与头像引用关联须共同成功。失败不改变当前头像或已有候选；数据库关联与业务状态共同提交，外部对象写入提前完成，不把对象存储或供应商请求放入长事务。重复提交不重复创建申请。
- 头像审核在关联提交后执行，遵循原可见范围和策略规则；机器和人工开关在候选创建时快照。上传成功不意味着审核通过，技能与头像分别展示审核状态。
- 更新页移除仅在提交成功后执行，立即恢复兜底并使待审候选失效，申请历史和失效图片保留策略不变。
- 未关联临时图片始终私有，按有界任务定期清理；关联与清理并发须保证不会删除已绑定图片。临时引用使用独立 `skill_avatar_upload` 表，24 小时过期；上传接口为 `/api/web/skills/avatar-uploads`，提交技能携带 `avatarAction`（默认 KEEP，可选 REPLACE/REMOVE）和替换时的 `avatarUploadId`。单独维护使用现有头像路径的 JSON 提交；更新携带 `expectedSlug` 校验技能包目标。清理和引用消费均锁定临时上传记录，发布与独立修改均采用技能→上传记录的锁顺序。不引入业务状态 SQL CHECK 约束。
- 唯一机器供应商的部署选择、后台两个审核开关、PRIVATE 直接使用规则保持不变。

原验收只覆盖详情页独立提交流程，不能证明上述新增／更新流程；本轮新增／更新及独立维护流程按对应测试和浏览器验收重新验证。真实供应商调用仍未验证。

同浏览器的发布、独立维护和审核决定成功后，须等待刷新技能展示、对应所有者头像状态、头像审核队列及技能内容审核队列缓存；不以等待缓存过期替代状态更新。回归以真实 QueryClient 下旧状态变为提交后的状态为 Oracle，并验证无关技能的所有者缓存不被失效。

## 裁剪组件选型调整（2026-10-13）

头像文件选择复用已有 `react-dropzone`，裁剪交互采用 `react-image-crop`（ISC，兼容项目 React 版本）。方形选区的拖动、缩放选区、触屏和键盘行为交由开源组件处理，移除自写居中裁剪与缩放交互。仅保留选区图像导出及私有上传／提交状态衔接，不改变审核、引用消费、保留／替换／移除规则。组件适配须验证非居中选区的实际导出结果、取消与迟到响应隔离，以及新增／更新／独立维护入口。

## 头像入口与弹窗简化（2026-10-13，用户人工反馈）

- 详情页仅保留标题旁头像，删除专门头像状态卡片、重复候选图、供应商开关说明及已批准审核理由。审核治理能力不因展示简化而移除。
- 我的技能自绘列表补齐名称旁头像，删除独立“管理头像”按钮与入口；统一“更新”页同时支持仅修改头像或上传新技能包。无技能包时只提交既有头像维护接口，不新增版本；有包时保留原子发布／头像关联流程。新建及驳回重提仍必须提供技能包。
- 使用已有 Tailwind CSS 视觉样式及 Radix Dialog 封装承载 React Image Crop，不引入新的整体 UI 框架。父表单为64像素头像和简短操作；裁剪弹窗画布有界、自适应，错误和重试在弹窗内。
- 弹窗取消／关闭／ESC恢复打开前草稿，上传确认成功后关闭弹窗并展示小预览；成功上传仍需父页面最终提交。更新页仅展示所有者需要处理的待审／失败／驳回信息及原有重试、申诉动作，保持治理闭环。

组件接入方式：仓库已有 `web/components.json`，本地 `shared/ui/Button`、`Dialog` 沿用 shadcn 的源码分发／组件组合方式，底层为 Radix 与 Tailwind。当前为 Tailwind 3 和旧 `default` 风格；本轮复用现有封装与主题，不重新执行 init，也不覆盖已有 Portal／焦点／主题定制。头像选择由本地预览、Button、Dialog 和 React Image Crop 组合，shadcn Avatar 的展示职责与图片裁剪／上传业务分开。

删除头像后的展示闭环：移除成功时，除当前头像状态外，还须等待已缓存但未挂载的技能列表／详情更新，避免返回列表短暂读取已删除的头像地址。本轮仅 REMOVE 使用 `refetchType: all`，KEEP／REPLACE沿用 active 刷新；回归用无 observer 的真实 QueryClient 数据验证刷新完成后再导航。弹窗高度约束设在 ReactCrop 根元素，以使库的图片继承明确的 `min(320px,45vh)`，并用实际浏览器测量验证。

## 统一技能审核与单改头像（2026-10-13，已确认，实施中）

本节取代以上历史实现中的“技能与头像独立人工审核”决定。

- 包与头像替换同次提交只生成一张技能审核申请；详情同时显示技能内容、当前头像与候选图。机器结果是该申请的审批条件，不是另一条人工审核流程。批准在同一事务发布版本及激活头像；驳回两者均不发布。
- 包与移除头像同次提交也在批准时共同生效；驳回保留原头像。单独移除仍无需审核，提交成功即生效。
- 单改头像不创建版本；需人工审核时以 SKILL_METADATA 进入同一技能审核队列，复用详情和批准／驳回动作。无人工审核时继续按头像策略直接使用或机器判定；PRIVATE规则保持。
- 权限完全复用技能审核规则：平台技能管理员／超级管理员可审核团队和全局申请，团队 OWNER／ADMIN 只能审核其空间；自审限制保持原技能审核语义。
- 新候选替换旧候选仍保留历史。关联旧候选的任务不能跳过头像单独批准内容；若候选已失效，整条批准失败，使用现有撤回／重提流程处理。机器未完成、异常或旧结果不能发布候选。
- 扩大可见范围所需的头像决定在同一技能申请中完成，不在批准内容后另建人工头像申请。部署供应商、密钥、审核开关及30天私有图片保留策略不变。
- 迁移保留旧数据和审计，兼容原版本／套件审核任务。业务状态约束放代码与测试，不增加 SQL CHECK。

申请留存边界：被替换／移除的候选及提交、决定、失效文字审计继续保留，关联的待审头像元数据任务可按既有撤回方式从活动队列删除，审计保留原任务关联。不得将撤回伪装为人工驳回。本期不扩展 ReviewTask 状态枚举或改变原技能包撤回语义。
