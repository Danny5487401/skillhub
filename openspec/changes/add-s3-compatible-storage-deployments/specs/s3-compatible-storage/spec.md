## Purpose

使部署方可以通过既有 S3 配置选择不同对象存储产品，同时维持技能文件、审核图片、下载链接和同步任务的可观察行为。支持范围由真实契约验收证明，不以供应商的兼容性宣传替代应用验证。

## ADDED Requirements

### Requirement: S3-01 统一协议配置
系统 SHALL 使用既有 `s3` 配置连接通过验收的 S3 兼容服务，保留 `local` 模式，不要求业务调用者按存储品牌选择接口。

#### Scenario: 更换空桶目标
- **WHEN** 新实例配置已准备的 RustFS 或 Silo 桶及有效业务凭证
- **THEN** 相同应用版本通过相同接口完成对象操作，无需修改技能元数据或指定品牌 provider

#### Scenario: 原有部署兼容
- **WHEN** 部署方沿用有效的 local 或外部 S3 配置
- **THEN** 原模式继续可用，不因新增选项自动更换后端

### Requirement: S3-02 对象操作完整性
系统 SHALL 保持对象键、字节、长度和内容类型的读写语义；单个和批量删除均不得将后端报告的失败当作全部成功。前缀统计 SHALL 明确数据是否完整。

#### Scenario: 特殊对象键往返
- **WHEN** 写入包含中文、空格和 URL 保留字符的合法对象键并读取元数据和内容
- **THEN** 键与内容不发生二次编码或截断，字节、长度和内容类型与输入一致

#### Scenario: 流式技能上传
- **WHEN** 上传的合法技能包包含超过 128 KiB 的文件并通过现有流式发布处理
- **THEN** 写入和下载字节与原文件一致，不因请求体重读而丢失内容或持续超时

#### Scenario: 私有上传暂存和失败清理
- **WHEN** S3 上传为签名和重试暂存请求体，或在暂存读取期间发生 I/O 或运行时异常
- **THEN** 暂存期间不放宽文件创建时的私有访问权限，在支持 POSIX 权限的平台保持仅运行身份读写；读取失败后清理尚未返回的暂存文件，并保留原始失败供调用方识别

#### Scenario: 批量删除部分失败
- **WHEN** 后端在批量删除响应中报告部分对象失败
- **THEN** 调用方能够识别失败，不得到全部删除成功的结论

#### Scenario: 前缀统计截断
- **WHEN** 对象数量超过一次分页或扫描上限
- **THEN** 继续分页或明确报告统计不完整，不将部分数量声明为总量

### Requirement: S3-03 端点与预签名契约
系统 SHALL 为实际访问方可达的端点生成预签名 URL，保留下载公开端点及同步上传内部端点的分工；不得通过事后改写已签名 URL 主机解决可达性。

#### Scenario: 内外网端点分离
- **WHEN** 后端使用内部端点，浏览器访问配置的公开端点，Worker 可达内部端点
- **THEN** 下载签名指向公开端点且读取成功，Worker 上传签名指向内部端点且上传成功

#### Scenario: 签名失效
- **WHEN** 使用过期、篡改签名或缺失签名要求的请求头
- **THEN** 存储拒绝请求，不返回对象内容或写入成功

### Requirement: S3-04 隔离与失败可见
系统 SHALL 维持现有私有对象与业务授权边界；凭证、网络和存储错误必须可观察，不得静默写入其他后端。凭证不得出现在公开链接、日志或报告中。

#### Scenario: 私有对象访问
- **WHEN** 匿名请求直接读取私有桶对象且无有效签名
- **THEN** 请求被拒绝，正常业务授权仍可生成限时下载链接

#### Scenario: 后端不可用
- **WHEN** 业务凭证无效、权限不足或目标网络不可达
- **THEN** 操作失败并提供可定位且脱敏的错误，不转写本地目录、不返回伪造成功
