## Purpose

为部署者提供可选的 S3 兼容存储交付方式、配置检查及可追溯的验收依据，并明确已有对象迁移参考的安全要求。新部署接入验证不代表支持生产迁移。新增选项不应使原有部署被自动替换，也不能把配置更新误认为数据已完成迁移。

## ADDED Requirements

### Requirement: DEP-01 存储选项独立部署
交付物 SHALL 提供 RustFS 和 Silo 可选 Compose 叠加配置，每次仅启用一个本地存储选项，数据卷独立；外部 S3 不要求启动本地存储。Helm SHALL 保留外部存储接入，不强制安装存储子 Chart。

#### Scenario: 选择本地存储
- **WHEN** 部署者按手册选择一种存储叠加配置
- **THEN** 应用通过稳定的内部服务地址连接所选服务，另一产品不会启动或共用数据目录

#### Scenario: 选择冲突
- **WHEN** 部署者试图同时选择两种本地存储选项
- **THEN** 交付预检明确拒绝此组合，不能静默选择其中之一

### Requirement: DEP-02 部署配置与凭证边界
端点、桶、凭证和产品 SHALL 由部署配置决定，变更通过重建相关服务生效，不进入系统设置表或后台热切换。示例 SHALL 区分初始化管理员凭证与应用业务凭证，默认不依赖应用自动建桶。

#### Scenario: 新实例初始化
- **WHEN** 部署者按示例准备桶和具备所需对象权限的业务账号
- **THEN** 应用无需存储 root 凭证即可运行，文档指出前缀统计所需的列举权限

#### Scenario: Worker 接入
- **WHEN** 启用 S3 模式 GitHub 同步
- **THEN** 手册要求 Worker 可达上传端点、允许目标主机并配置有效 staging 容量预算，完整导入与清理能够验收

### Requirement: DEP-03 可验证的交付与兼容声明
交付 SHALL 记录应用修订、被测产品版本、不可变镜像摘要、架构和验收结果。配置检查与真实对象诊断必须区分，服务存活不能替代真实操作。旧镜像别名 SHALL 保持兼容，映射文件修改不能视为目标镜像已刷新。

#### Scenario: 发布接入验证矩阵
- **WHEN** 宣布某个产品版本通过新部署接入验证
- **THEN** 共享契约和关键业务路径有真实结果，未执行项及限制被列出，阻断用例失败时不能声明通过
- **AND** 不将接入结果扩大为产品最优推荐、长期稳定性、大规模、高可用或生产迁移支持

#### Scenario: 运行诊断
- **WHEN** 操作者执行存储诊断
- **THEN** 在专用前缀进行有时限的真实对象操作并清理，失败非零退出，不泄露密钥或触碰业务对象

### Requirement: DEP-04 逻辑迁移与回退参考
迁移参考 SHALL 明确本次不宣称生产迁移支持；仅有独立测试桶小样本演练，未验证旧 MinIO/local 真实迁移或大规模生产迁移。迁移参考 SHALL 要求保留对象键和必要元数据、校验内容、暂停相关写入并完成最终同步后切换。不同产品不得默认复用原始数据卷；切换配置不代表迁移完成。

#### Scenario: 已有数据切换
- **WHEN** 实例从现有存储迁往另一产品
- **THEN** 先备份复制，再停写并处理在途任务，校验最终差异，验证发布下载和同步后才恢复写入

#### Scenario: 接受新写入后回退
- **WHEN** 新后端已经接受业务写入但需要回退
- **THEN** 指南要求再次停写并协调新增和删除差异，不能仅切回旧端点导致对象丢失或已删除数据复活
