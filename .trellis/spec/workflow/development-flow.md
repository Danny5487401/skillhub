# 开发与交付流程

## 轻量使用分层

| 情况 | 使用方式 |
|---|---|
| 文案、小修或补规范 | 读取相关规则，直接修改验证，不强制建任务 |
| 多步功能 | 使用任务记录保存需求、上下文、进度、验证；尊重用户已有不创建任务的选择 |
| 大型需求或架构调整 | [OpenSpec](./openspec.md)明确正式需求设计，Trellis组织执行接续 |
| 已有权威文档 | 引用详细契约，关键规则可在 AGENTS 重复；变更时核对入口与正文一致 |
| 换worktree | 从本机模板显式同步可复用规则及工具配置，任务各自管理；已跟踪spec以分支内容为准，模板更新必须比较后显式应用 |

## 实现与交接

从[总索引](../index.md)选择领域与专题，无需工程 Skill 自动触发。需求不清先澄清。
实现前明确行为差距、影响文件、来源与验证方式。实现和检查使用同一组正文，检查再追加[测试入口](../testing/index.md)。
有任务时复用现有上下文清单；无任务时直接传递路径与范围，不补建任务。
文件存在、Skill可见或hook配置不等于实际读取。

## 开发环境

命令以[Makefile](../../../Makefile)和[开发手册](../../../docs/dev-workflow.md)为准，版本查POM/package.json。
启动停止先确认服务与数据，重置、推送、PR、发布不是普通检查。热更新不替代验证。
并行环境见[手册](../../../docs/13-parallel-workflow.md)，不默认操作其他实例。

## 检查与PR

按测试入口区分快速反馈与交付门槛。API变化检查消费者和生成类型，运维变化检查Smoke，文档检查引用。
提交前检查diff、生成文件和敏感信息；不自动提交、推送、创建PR或部署。
标题和提交采用 `<type>(<scope>): <description>`，type为feat/fix/docs/test/refactor/chore，scope为受影响领域。
一次提交一个逻辑变化。PR说明问题、改变后的行为、必要实现细节、验证及兼容影响，参考[贡献指南](../../../CONTRIBUTING.md)与[PR模板](../../../.github/pull_request_template.md)。
评审给适用规范和源码证据，不以个人偏好替代规则。

## 收尾

区分通过、失败、未运行和环境受阻。复用经验写所属专题，普通修复不强制新增规则。
已有任务或清理worktree时读[归档](./task-archive.md)；不存在记录不为归档补建任务。
