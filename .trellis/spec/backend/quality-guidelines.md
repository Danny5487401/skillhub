# 后端质量与行为验收

本页定义检查什么；测试层次、fixture、真实依赖与运行方式见 [后端测试](../testing/backend-testing.md)，
交付门槛见 [测试入口](../testing/index.md)。

| 改动 | 应观察的结果 |
|---|---|
| 分层与模块 | 新依赖方向符合模块约定，领域不返回 app DTO，查询投影没有挤入编排服务 |
| API/DTO/兼容协议 | 成功与错误结构、空值/分页及消费者预期一致，生成类型没有未解释漂移 |
| 授权/命名空间 | 允许场景成功；匿名、无权限、跨命名空间或伪造身份被正确拒绝且不产生写副作用 |
| 状态机/事务 | 前后状态、版本指针和读模型符合正式契约；失败不留下不允许的中间状态 |
| 并发/重复请求 | 竞争结果与契约一致，无重复副作用或旧状态覆盖；锁定后重新判断有效状态 |
| 仓储/迁移 | 查询、排序、total与权限一致；实际数据库执行及存量升级得到验证 |
| 外部服务/队列 | 失败和超时可观察；重试、终态、确认与清理顺序不会丢失必要恢复信息 |
| 日志/异常 | 请求可关联，敏感信息不输出，错误映射与消息资源匹配 |

## 项目经验：Maven 多模块旧缓存

仅在 app 下执行 `./mvnw -pl skillhub-app clean test` 可能使用本地仓库中陈旧的依赖产物，出现误导性的符号或签名不匹配。
使用仓库 `make test-backend-app`（含依赖模块）或更广的 `make test-backend`；故障排查先确认实际构建模块，不能通过改业务代码迎合旧产物。
命令实现以 [Makefile](../../../Makefile) 为准。

单测通过、真实依赖集成通过、环境健康与生产验收分别报告；静态阅读测试文件不算运行测试。
