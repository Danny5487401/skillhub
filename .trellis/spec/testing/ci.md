# CI 检查与证据

修改流水线、路径过滤、测试入口或交付门槛时读取。工作流名称不证明它运行了什么，
必须核对 `on`、job/step 条件、矩阵和执行命令。

## 读取入口

- [pr-tests.yml](../../../.github/workflows/pr-tests.yml)：前端构建/单测、后端单测、条件性文档构建。
- [pr-e2e.yml](../../../.github/workflows/pr-e2e.yml)：当前启动开发栈并执行前端 E2E，
  不能沿用“仅 staging smoke”的旧描述。
- [pr-cli.yml](../../../.github/workflows/pr-cli.yml)：CLI 平台矩阵、lint/typecheck/test/build 与 Node 运行验证。
- [工作流目录](../../../.github/workflows/)：脚本、Helm、Scanner 等其他路径按变更追加，不在此复制易过期完整清单。

## 质量要求

1. 路径过滤要覆盖源代码、共享依赖、锁文件和检查自身；没有触发不等于检查通过。
2. 修改聚合结果或退出处理时验证成功、失败、跳过和取消传播；不能吞掉失败或仅检查进程启动。
3. draft 跳过、路径无关跳过、环境失败、用户取消分别报告。只有运行过且断言通过才算相应范围通过。
4. 需要的分支保护检查以实际仓库配置为准；仅看到 YAML 不声称已设为 required。
5. 工具版本以各模块清单和工作流实际配置核对；发现不一致记录差异，不在规范整理时顺手升级。
6. 测试产物、构建产物、镜像发布和真实部署分别证明。产物应关联被检查的提交，旧运行不覆盖后续改动。

本地反馈和交付按[选测矩阵](./index.md)执行；CI必需检查仍以实际仓库配置为准。
本文件不赋予跳过适用门槛、触发部署或发布的权限。
