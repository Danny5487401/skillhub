# 跨层修改判断

适用于前端、API、CLI、领域、持久化、扫描边界的变化。只沿受影响路径分析。

1. 梳理输入→转换→状态变更/存储→响应→消费者，指出契约的权威来源。
2. Web、CLI、兼容接口、后台任务哪些消费者受影响？生成类型是否要更新？
3. 区分格式校验、身份授权、领域不变量与数据库结构完整性；入口校验不能替代后续授权和状态检查，也不在每层重复相同规则。
4. 成功、拒绝、超时、取消、重试和并发时，哪些状态已经改变？外部副作用能否回退？
5. 新旧版本并行是否兼容？配置、迁移、应用与消费者的发布顺序是什么？
6. 哪个断言能发现最可能的错误？类型通过能否证明失败后的状态正确？
