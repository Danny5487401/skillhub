# 代码复用判断

新增 helper、组件、服务或合并相似代码前，先找已有实现、调用方与测试。

- 相似代码是否表达同一业务概念，还是写法碰巧相似？
- 调用方是否应因同一原因一起变化？变化原因不同通常应保留独立实现。
- 提取后依赖方向是否正确？不要为了共用把业务规则塞入通用 UI 或底层工具。
- 抽象是否减少理解成本，还是增加开关、可选参数和隐藏状态？
- 有无已有组件、类型、schema、仓储或解析入口可用？
- 修改共享实现影响哪些调用方，怎样证明旧行为保持？

次数、行数和相似度不是自动抽象阈值。外部数据解析需要明确契约归属，但不因此要求新建通用解码框架。
