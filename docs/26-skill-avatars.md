# 技能头像与审核

技能所有者可在新增／更新技能页面选择自定义 PNG/JPEG 头像，网页提供方形裁剪和缩放；不提供预设图标。更新默认保留头像，也可替换或移除。“我的技能”统一从“更新”入口维护，也可只改头像而不发布新版本；详情页仅在标题旁展示当前头像。服务器仍会独立校验：输入不超过 2 MB、边长不超过 1024 像素，并重新编码为 PNG，避免依赖客户端裁剪或保留原图元数据。头像候选存在私有对象存储；审核完成前，公众继续看到旧头像或技能名首字母。所有者在“我的技能”和更新页可查看已提交头像的缩略图及审核状态，待审头像不会替代公开头像；加载失败会提示重试。

## 上传与提交

选择图片后先裁剪并上传到私有存储，上传成功后才允许提交技能或头像修改；未选择头像也可提交新技能。上传失败可重试，但不能把失败或尚未完成的上传随技能提交。上传成功仅表示文件已保存，不表示审核通过。

提交成功后图片才关联到技能并进入对应审核流程。更新时未修改头像会保留原头像；选择移除时先预览首字母。仅改头像时提交成功即恢复兜底；与新技能包一起提交时在同一申请审核通过后移除，驳回保留原头像。失效候选历史保留。取消编辑或提交失败不会改变原头像及已有待审申请。未关联的临时图片保持私有；上传引用 24 小时后过期，过期未关联图片由清理任务定期回收，提交时过期需要重新上传。

技能包与头像同次提交时只有一张技能审核申请：审核员在原技能审核详情同时检查内容与头像，一次批准或驳回，共同生效。机器结果作为同一申请的审批条件，不能提前发布头像。单改头像不创建新技能版本；需要人工决定时仍进入原技能审核队列，标明“头像修改”，不再有独立头像审核队列。

## 审核策略

超级管理员在“系统配置”中分别开关机器审核和人工审核。默认关闭机器审核、开启人工审核。单改头像时，两个开关都关闭直接发布；只开启机器时通过即发布、阻止或未知结果保持私有；只开启人工时进入技能审核队列；两者都开启时先机器后人工。若与技能包同次提交，则不论头像开关如何，仍等待原有技能内容审核共同批准。机器阻止后所有者可申请人工复核；机器服务失败时可重试，不会自动放行。当前云供应商不能提供可证明不可变的模型版本，不跨申请复用机器结果；新申请重新检测。每次调用记录实际服务／API版本和内部审核策略revision，未知模型版本留空，不把SDK或API版本作为模型版本。扩大可见范围时必须重新人工审核。`PRIVATE` 技能头像由所有者直接使用。

人工权限复用技能审核：团队管理员可审本团队，平台技能管理员／超级管理员可审团队和全局；自审限制也沿用原技能审核规则。头像只能由技能所有者提交、替换或删除；管理员可审核和撤下，不可代传。新申请使旧待审申请失效；旧审核决定不能覆盖新头像。被拒绝、替换、删除的候选图片私有保留 30 天后清理，文字审核记录继续保留。头像撤下后显示首字母兜底。

新提交若可见范围扩大，系统在同一技能申请中关联目标范围头像候选，审核完成后共同生效，不能先发布内容再要求另一次人工审核。遗留数据的范围补偿仍保证未经目标范围批准的头像不向新增受众公开。已有相同目标范围的待审申请不会被覆盖；新旧候选使用不同对象键，避免旧文件到期清理影响当前头像。自动建候选失败时旧头像仍保持隐藏；每五分钟分批检查并补建候选。若候选已建但机器读取或审核失败，状态记为 `ERROR`，一小时冷却后自动重试；同一候选自动审核最多调用三次（含首次），到达上限后由所有者在冷却结束后主动重试或重新提交。普通上传在机器调用前宕机留下的 `PENDING` 候选，以及机器处理中宕机留下的 `PROCESSING` 候选，十分钟后也由补偿任务重领。机器调用前后分别使用短事务核验候选指针，外部调用期间不持有数据库锁；过期尝试的迟到结果不会激活头像。当前发布版已驳回的自动申请不会反复入队，历史发布版的驳回不阻止新发布。服务日志仅记录技能或候选 ID 和异常类型，不记录可能包含凭证的供应商请求信息。`PRIVATE` 头像及候选图片只有技能所有者可以读取。

## 部署配置

### 机器结果与人工决定

机器审核结果与申请的最终决定是两个状态。以下针对非 `PRIVATE` 的单改头像；与技能包同时提交时，仍需等待原技能审核共同决定。

| 机器结果 | 开启人工审核 | 未开启人工审核 |
| --- | --- | --- |
| 通过（`PASSED`） | 进入统一技能审核，批准后生效 | 自动生效 |
| 阻止（`BLOCKED`） | 新头像保持私有，申请待审；审核员可拒绝，或填写明确理由后人工改判 | 不生效，不自动变为人工驳回；所有者可申请人工复核 |
| 异常（`ERROR`） | 保持私有，不允许直接批准；先重试得到有效结果 | 保持私有，等待重试 |

文件上传成功不等于机器通过；机器阻止也不等于管理员已经拒绝。人工拒绝后，用户可查看提交图片及拒绝原因，公开头像保持旧图或首字母兜底。机器阻止没有自动驳回整个技能申请，避免把机器判断与人工决定混为一谈。

### 供应商与凭证

在部署密钥配置中指定唯一供应商及其凭证，然后才可从后台开启机器审核。Spring 属性如下；将值映射到部署 Secret/环境变量时请遵循当前部署平台的配置方式，不要写入仓库或后台数据库：

| 供应商 | 属性 |
| --- | --- |
| 通用 | `skillhub.avatar.moderation.provider`：`xfyun` 或 `aliyun` |
| 讯飞 | `skillhub.avatar.moderation.xfyun.app-id`、`skillhub.avatar.moderation.xfyun.access-key-id`、`skillhub.avatar.moderation.xfyun.access-key-secret` |
| 阿里云 | `skillhub.avatar.moderation.aliyun.access-key-id`、`skillhub.avatar.moderation.aliyun.access-key-secret` |

后台只显示两个启停开关，不回显供应商或密钥。阿里云适配器使用上海地域的 `profilePhotoCheck`，通过短期上传令牌把私有候选送到官方 OSS 临时对象，再调用同步审核；不会公开候选 URL。官方返回 `RiskLevel=none/low` 通过，`medium/high` 保持私有并允许人工复核。把 `medium` 归为阻止是本产品策略。响应非 200、空结果或未知值均不放行。机器接口可能按量计费，开启前由部署方确认供应商账号与费用。

阿里云须开通内容安全增强版，测试凭证至少需要 `yundun-greenweb:DescribeUploadToken` 和 `yundun-greenweb:ImageModeration` 权限。当前使用供应商临时上传令牌，无需部署方自建审核用 OSS Bucket 或向该凭证授予自有 OSS 全权限。[官方本地图片接入示例](https://help.aliyun.com/zh/document_detail/467828.html)即使用该流程。阿里云说明上传到其临时存储的本地图片保留 30 分钟；这与 SkillHub 私有候选图片保留 30 天是两个独立生命周期，见[官方接口说明](https://help.aliyun.com/document_detail/467829.html)。

切换部署供应商需要更新服务配置并重启应用。已有候选保留提交时的供应商与机器／人工开关快照，不自动迁移；尚需调用旧供应商的申请在切换后会得到 `ERROR`，不会偷偷改用新供应商。所有者应重新提交以使用新供应商；已经完成的机器结果不会因切换配置被重新检测。

讯飞官方图片审核接口要求把 `accessKeySecret` 放在请求 URL 参数中。应用不会记录完整 URL 或异常原文，但 Java HTTP 客户端调试日志、反向代理、出口代理、链路追踪及第三方日志仍可能记录该 URL。部署方使用讯飞适配器前，必须确认相关组件不采集请求 URL，限制凭证权限并建立轮换机制。若无法满足，先不要开启该适配器。

## 与原 Issue 的差异

原 Issue 提议自动图片审核；本期产品决策改为“上传、裁剪、机器审核可选、人工审核可选”的四种策略。默认使用人工审核，机器审核仅在部署好单一供应商且管理员开启后运行。个人头像不在本期范围。

## 验收要点

分别验证四种开关组合、候选与当前头像隔离、拥有者和审核员权限、审核通过/驳回/复核、相同图片的新申请重新检测及每次策略审计、未知机器结果不放行、连续替换后旧审核无效、删除后首字母兜底、30 天清理以及团队/全局可见范围变化。外部供应商真实计费调用需要部署方测试账号与授权；单元测试使用模拟响应。
